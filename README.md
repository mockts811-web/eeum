## 추진 배경 및 목적

대중교통 분실물 처리 과정에서 시민은 다음과 같은 어려움을 겪습니다.

- **문의처 분산:** 습득물이 지하철 유실물센터, 버스 운수회사, 경찰서에 나뉘어 보관되며, 일정 기간(7일)이 지나면 경찰서로 이관됩니다.
- **검색 접근성 부족:** 기존 조회 방식은 분류·날짜·지역을 각각 선택해야 하며, "어제 2호선에서 검은 가죽 반지갑"과 같은 자연어로는 검색할 수 없습니다.
- **초기 대응 수단 부재:** 하차 직후에는 열차·버스가 운행 중이어서 종점 도착 전에 연락하면 회수 가능성이 높지만, 탑승 차량의 현재 위치를 확인할 방법이 없습니다.

기관 담당자 역시 습득물마다 항목을 직접 나눠 입력해야 하며, 담당자마다 표현이 달라 검색 품질이 떨어집니다.

유실물 e음은 **공공데이터와 생성형 AI**를 활용해 분실물 검색·신고·수령 과정을 간소화하는 것을 목표로 합니다.

| 대상 | 추진 목표 |
|---|---|
| 시민 | 자연어 한 문장으로 기관별 습득물을 통합 검색하고, 하차 직후 탑승 차량 위치와 연락처를 즉시 안내 |
| 기관 담당자 | 메모와 사진만으로 습득물 등록 항목을 자동 정리하고, 수령 신청과 본인 확인을 한 화면에서 처리 |

<br>

## 주요 기능

### 시민 서비스

#### 1. AI 문장 검색
"11월 12일에 흰색 햄스터 카드지갑을 잃어버렸어요"처럼 **문장으로 적으면** AI가 분류·색상·날짜·노선·특징을 찾아 검색 조건으로 채우고, 지하철·버스·경찰서 습득물을 **유사도 순**으로 보여 줍니다.

- 물건이 여러 개거나("검은 아이폰이랑 흰 에어팟") 노선을 갈아탄 경우도 나눠서 찾습니다.
- 각 후보에 **일치 이유**("색상·날짜·분류가 같아요 / 특징 '햄스터'도 같아요")와 유사도 점수를 함께 보여 줍니다.
- AI가 찾은 조건은 화면에서 바로 고칠 수 있습니다.

 <img width="1071" height="781" alt="02-search" src="https://github.com/user-attachments/assets/9003d4d3-fe70-4eaf-aa12-9981497b2064" />


#### 2. 수령 신청
습득물 상세 화면에서 **"내 물건이에요"** 신청을 보냅니다.

- 공개되지 않은 **안쪽 특징**(내용물·각인·잠금화면)을 적으면, 담당자가 비공개 메모와 맞춰 봅니다.
- 본인 수령과 **대리 수령**(대리인 이름·관계·연락처)을 고를 수 있습니다.
- 신청하면 **확인 메일**이 오고, 담당자 화면에 바로 나타납니다.


<img width="1061" height="912" alt="03-claim" src="https://github.com/user-attachments/assets/f9f6366b-84cd-4025-8b38-9a00807f3e48" />


#### 3. 당일 분실 (방금 두고 내렸어요)
내린 노선·정류장·시각·방향을 고르면 **탔던 열차·버스가 지금 어디쯤 있는지** 보여 주고, 바로 연락할 곳과 문의할 때 알려 줄 정보를 정리해 줍니다.

- **지하철 1~9호선:** 열차 시간표로 탔던 열차를 찾고, 실시간 열차 위치와 맞춰 봅니다.
- **그 밖의 노선과 서울·경기·인천 버스:** 실시간 위치와 구간 속도로 계산합니다.
- 문의 정보(노선·방향·열차번호·내린 역·시각·물건)는 버튼 하나로 복사합니다.

#### 4. 비슷한 물건 알림
아직 등록되지 않은 물건은 **알림 조건을 저장**해 두면, 매일 오전 9시와 오후 6시에 새 습득물과 비교해 **유사도 60 이상**이면 이메일로 알려 줍니다.

- 저장하면 확인 메일이 옵니다.
- 로그인 없이 **이메일 확인 코드**로 내 알림과 진행 단계(조건 저장 → 비교 중 → 후보 발견 → 수령 완료)를 불러옵니다.

### 기관 담당자 서비스

#### 1. AI 습득물 등록
사진과 메모 한 줄("오늘 2호선 홍대입구역 승강장, 남색 학생증 카드, IC칩 / 비공개: 카드 위 끝쪽 껍질 까짐")을 넣으면 AI가 **등록 항목으로 나눠** 줍니다.

- 분류·색상·물품명·습득 장소·습득일·공개 특징·주인 확인용 비공개 메모로 정리합니다.
- 사진에서만 보이는 특징은 "(사진 확인 필요)"로 표시해 담당자가 확인하게 합니다.
- 이름·전화번호·카드번호 같은 **개인정보는 AI에 보내기 전에 가리고**, 신분증·카드처럼 개인정보가 찍히기 쉬운 물건은 경고합니다.
- 지갑·휴대폰·카드 같은 물건은 **고액·귀중품**으로 자동 표시합니다.

#### 2. 보관 물품 조회·수정
문의 전화 내용을 문장 그대로 넣으면 AI가 **유사도 순**으로 찾아 줍니다.

- 보관 중 / 고액·귀중품 / 기한 임박 / 이관 대상 / 수령 신청 / 수령 완료로 나눠 봅니다.
- 습득일 오래된 순·최신순·유사도 순으로 정렬합니다.
- 7일이 지난 지하철·버스 습득물은 경찰서 이관 대상으로 자동 분류됩니다.

#### 3. 수령 신청 처리
시민이 보낸 신청이 목록 맨 위 안내 띠와 **수령 신청** 페이지에 모입니다.

- 시민이 적은 안쪽 특징과 비공개 메모를 나란히 보여 주고, **겹치는 말**을 표시합니다.
- 수령 확인 창은 필수 확인 항목(신분증 확인, 주인만 아는 특징, 대리 수령이면 대리인 이름·관계·위임 서류)을 **모두 체크해야** 기록됩니다.

## 접속 및 실행 방법

### 1. 웹 서비스 접속 (권장)

**https://mockts811-web.github.io/eeum/**

- 시민 기능은 로그인 없이 바로 쓸 수 있습니다.
- 담당자 화면은 오른쪽 위 **기관 담당자**를 누르고, Supabase에 등록된 담당자 계정으로 로그인합니다. 계정은 팀에 요청해 주세요.

### 2. 로컬 실행

화면은 `index.html` 한 파일이라 따로 빌드할 것이 없습니다. 다만 열차 시간표 파일(`data/timetable/`)을 불러와야 해서, **파일을 더블클릭하지 말고 간단한 웹 서버로 여는 것**을 권장합니다.

```bash
# 1) 저장소 받기
git clone https://github.com/mockts811-web/eeum.git
cd eeum

# 2) 웹 서버 켜기 (아래 중 하나)
python3 -m http.server 8000
# 또는
npx serve . -l 8000

# 3) 브라우저에서 열기
open http://localhost:8000        # macOS
# Windows: start http://localhost:8000
```

로컬 실행 시 차이점:

| 기능 | 동작 |
|---|---|
| 습득물 목록, 수령 신청, 알림, 당일 분실 | 배포 사이트와 같은 서버(Supabase)를 써서 똑같이 동작합니다 |
| AI 문장 검색·AI 등록 정리 | 보안상 배포 주소에서 온 요청만 받도록 막혀 있어, **규칙 기반 정리로 대신** 동작합니다. AI 결과를 보려면 배포 사이트를 쓰거나, 내 Supabase에서 `ALLOWED_ORIGINS`에 `http://localhost:8000`을 추가하세요 |

### 3. 시연 모드 (서버 연결 없이 실행)

`index.html`의 `CONFIG`에서 `SUPABASE_URL`을 빈 값(`''`)으로 바꾸면, 서버 없이 **가상 데이터로** 모든 화면을 둘러볼 수 있습니다. 담당자 화면은 아무 이메일·비밀번호로 들어가집니다.

## 시스템 구성

```
[브라우저: index.html]
   │  시민 화면 · 담당자 화면 (HTML · CSS · JavaScript 한 파일, 빌드 없음)
   │
   ▼
[Supabase]
   ├─ PostgreSQL + RLS ........ 습득물 · 기관 · 수령 신청 · 알림 (행 단위 권한)
   ├─ Auth ................... 기관 담당자 로그인
   ├─ Storage ................ 습득물 사진
   ├─ Edge Functions (Deno) .. AI 정리, 실시간 위치, 데이터 수집, 메일
   └─ pg_cron ................ 알림 비교(매일 09:00·18:00), 경찰서 이관(매일 00:05), 사진 AI 분석
         │
         ▼
[외부 API] Gemini · 경찰청 습득물 · 서울/경기/인천 실시간 교통 · Gmail SMTP
```

- 배포: GitHub Pages (`main` 브랜치에 push하면 자동 반영)
- 비밀 키는 코드에 없고, 모두 Supabase Secrets에만 있습니다.

### 유사도 점수
목록 순서는 화면에서 아래 식으로 계산해 0~100으로 보여 줍니다.

```
유사도 = 100 × (0.45 특징 일치 + 0.20 색상 + 0.15 날짜 + 0.10 습득장소(노선) + 0.10 분류)
```

- 85 이상 "유사도 높음", 60 이상 "보통", 그 아래는 "낮음"으로 표시합니다.
- 비슷한 물건 알림은 Gemini가 후보를 다시 비교해 60 이상일 때만 메일을 보냅니다.

```
├─ 3_staff.sql                     담당자 계정 ↔ 기관 연결
├─ 4_cron.sql                      자동 실행 예약 (알림 비교, 경찰서 이관)
├─ photo-ai/                       사진 AI 분석으로 공개 특징 자동 보강 (폴더 README 참고)
└─ functions/

   ├─ auto-analyze-items/          수집된 사진을 AI로 분석해 공개 특징 보강
   ├─ match-alerts/                알림 조건과 새 습득물 비교 → 메일
   ├─ alert-mail/                  알림 저장 확인 메일
   ├─ alert-lookup/                이메일 확인 코드로 내 알림 불러오기
   └─ claim-mail/                  수령 신청 확인 메일
scripts/, tests/, audit/           사진 AI 빌드·테스트·검증 기록
```

## 배포 환경 구축

별도의 Supabase 프로젝트에 서비스를 새로 구축하는 절차입니다.

1. **SQL Editor**에서 `1_schema.sql` → `2_seed.sql` 순서로 Run
2. **Authentication → Users → Add user**로 담당자 계정을 만들고, `3_staff.sql`의 이메일을 바꿔 Run
3. **Edge Functions**에 `supabase/functions/` 아래 함수를 배포하고(Verify JWT 끄기), 아래 Secrets 등록
4. `4_cron.sql`을 Run해 자동 실행을 예약 (Vault에 `project_url`, `cron_secret` 필요)
5. `index.html`의 `CONFIG`에 Project URL과 Publishable key 넣기

| 함수 | 필요한 Secrets |
|---|---|
| ai-parse | `GEMINI_API_KEY`, `GEMINI_MODEL`, `ALLOWED_ORIGINS`(선택), `IMAGE_URL_HOSTS`(외부 사진 분석 시) |
| transit-locate | `SEOUL_SUBWAY_KEY`, `SEOUL_BUS_KEY` |
| fetch-police-items | `POLICE_API_KEY`, `PORTAL_API_KEY`, `CRON_SECRET` |
| auto-analyze-items | `CRON_SECRET`, `PHOTO_AI_WORKER_SECRET` |
| match-alerts | `GEMINI_API_KEY`, `GEMINI_MODEL`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `CRON_SECRET` |
| alert-mail, alert-lookup, claim-mail | `GMAIL_USER`, `GMAIL_APP_PASSWORD` |

- `index.html`의 `sb_publishable_…` 키는 공개용이라 노출돼도 됩니다. `secret`·`service_role` 키는 절대 HTML에 넣지 마세요.
- Gemini 키가 없으면 규칙 기반 정리로, 실시간 위치 키가 없으면 시간표 기반 계산으로 동작합니다. 어느 경우에도 화면은 멈추지 않습니다.

## 개인정보 보호 및 보안

| 데이터 | 시민 (로그인 없음) | 기관 담당자 |
|---|---|---|
| 습득물 (items) | 수령 완료 전 물품 조회 | 자기 기관 물품 조회·등록·수정·삭제 |
| 주인 확인용 비공개 메모 | ✕ | 자기 기관 물품만 |
| 수령 신청 (claims) | 보내기만 (조회 ✕) | 자기 기관 물품의 신청만 |
| 수령 기록 (pickups) | ✕ | 자기 기관 물품만 |
| 알림 조건·이메일 (alerts) | 등록만 (조회는 이메일 확인 코드로만) | 등록만 |

- 서버 로그에는 입력 문장과 이메일 주소를 남기지 않습니다.
