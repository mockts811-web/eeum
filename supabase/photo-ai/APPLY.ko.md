**최종 요청: 기존 물품과 새 물품 모두 사진을 분석해 공개 특징에 자동 저장**

사용자가 공개 특징 자동 반영을 명시적으로 요청했으므로, 이전의 비공개 저장/담당자 저장 방식에서 서버 자동 추가 방식으로 변경했습니다. 물품 설명의 실질적인 내용은 유지하고, 정해진 습득/보관 상투 문구는 제거합니다. 원문과 변경 후 값은 비공개 이력에 보관합니다. 분류·색상 코드·물품명·비공개 메모는 변경하지 않습니다.

현재 프로젝트에는 이미 적용됐습니다. 아래는 새 프로젝트 설치/복구용 절차이며 운영에 설치 SQL을 다시 실행하지 않습니다.

**최초 설치 순서**

1. 00_preflight.sql로 DB·Storage·기존 함수/예약을 확인하고 정의·권한·소스·예약 해시를 백업합니다. 비밀값은 출력하지 않습니다.
2. 01_install.sql을 적용합니다. 기존 설치가 있으면 이 단계를 생략합니다.
3. 90_pause.sql로 새 자동화를 멈추고 진행 중 작업이 끝난 뒤 08_public_features.sql, 이어서 09_tidy_public_descriptions.sql을 적용합니다. 최초 설치도 두 확장이 필요합니다. 기본 publish_public=false입니다.
4. auto-analyze-items 작업자를 배포합니다. 기존 ai-parse와 수집기는 재배포하지 않습니다. 현재 배포 작업자 v2는 그대로 재사용할 수 있습니다. 헤더 자체 인증이므로 작업자 JWT 검증은 끕니다. 서버 Secret은 PHOTO_AI_WORKER_SECRET 우선, 없으면 기존 CRON_SECRET입니다. 같은 값을 Vault에서 참조하고 클라이언트에 공개하지 않습니다.
5. 인증된 POST {} 또는 {"dryRun":true}로 상태만 조회합니다. 작업/공개 저장은 하지 않습니다.
6. 아직 분석하지 않은 승인 범위 물품으로 configure('pilot',물품ID,20), control.publish_public=true를 설정하고 작업자에 {"dryRun":false,"itemId":"물품ID"}를 1회 호출합니다. 실제 items.description 추가와 publications.previous_description 보관을 확인합니다. 기존 완료 작업을 초기화하지 않습니다.
7. 새 예약이 없을 때만 04_create_cron_disabled.sql로 eeum-photo-ai-v1을 만듭니다. 전용 Vault 이름이 없으면 기존 project_url/cron_secret을 재사용합니다. 다른 팀의 예약은 변경하지 않습니다.
8. 공개 자동화와 기존 사진 분석이 승인된 범위에서 07_enable_public_all.sql을 실행합니다. 기존 대기 등록, all 모드, 공개 저장, Cron 활성화를 한 트랜잭션으로 설정합니다. 기본 상한은 300작업/일이며 전역 1작업/분입니다. 기존 물량과 실패 횟수에 따라 날짜를 넘길 수 있습니다. Gemini 내부 400 대체 호출 때문에 작업 수와 AI 요청 수는 다를 수 있습니다.

**공개 문장 정리**

기존 수동 버튼의 문장 정리 목적에 맞춰, 정해진 습득/보관 상투 문구만 SQL 규칙으로 제거합니다. 예: 프라다 지갑(블랙(검정)색), 사피아노 패턴, 덮개형, 금속 로고. 괄호·모델명·금액·실질적인 메모는 보존합니다. AI를 다시 호출하지 않습니다. 사진이 없는 외부 물품도 기본 문장은 정리하며, 담당자 직접 등록/수령 완료 물품은 제외합니다.

이미 저장된 문장은 승인 범위에서 eeum_photo_ai_backfill(NULL,1000)으로 대조하면 정리됩니다. 같은 버전의 완료 분석을 초기화하지 않습니다. 1,000건을 넘으면 커서 또는 정기 대조로 이어갑니다.

**무엇을 공개하는가**

기존 ai-parse의 photoFeats·color·privacy를 그대로 재사용합니다. privacy가 false인 결과만 후보가 되며, 색상·재질·외형의 내부 허용 어휘로 완전히 설명되는 짧은 제안만 공개합니다. 예: 접이식, 가죽 재질, 사피아노 패턴, 덮개형, 금속 로고. 이름·번호·영문 자유문·URL·지시문·부정 표현은 제외합니다. 후보 중 원래 설명에 없는 최대 4개만 추가합니다. 이 어휘표는 공식 코드표나 AI의 시각적 판단 정확성을 보증하지 않습니다.

개인정보 의심 또는 안전한 새 특징이 없으면 기존 설명을 유지합니다. 정해진 상투 문구 외의 기존 설명은 삭제하지 않고, 비공개 메모를 읽어 공개하지 않습니다. AI 추출 오류가 완전히 없다고 주장하지 않습니다.

**중복·사진 변경·실패 처리**

Storage metadata.eTag가 유효하면 파일 내용 표식과 경로/크기/MIME으로 같은 사진을 식별합니다. 수집기의 같은 사진 upsert로 object.version이 바뀌어도 같은 ETag이면 재분석하지 않습니다. ETag가 없는 객체만 기존 version/updated_at 기준으로 대체합니다. 이미지 바이트를 별도 다운로드해 SHA-256을 계산하는 구현은 아닙니다.

업그레이드 시 현재 객체와 일치하는 기존 완료 결과의 버전 표기만 전환하고 상태·시도 횟수는 초기화하지 않습니다. 새 사진 내용 또는 경로가 바뀐 경우만 새 대기에 들어갑니다. 신규/기존 기본 이미지·사진 없음·잘못된 경로·원격 URL만 남은 사진·8,000,000바이트 초과·지원하지 않는 형식은 제외합니다.

AI 일시 실패는 최소 5분/15분 대기 후 최대 3회입니다. 대기 작업이 많으면 실행은 더 늦어집니다. 인증/모델/응답 계약 오류는 자동화를 일시 중지합니다. 공개 DB 저장만 실패하면 분석 결과를 비공개로 보존하고 정기 대조에서 저장만 다시 시도합니다. 이 복구로 Gemini를 새로 부르지 않습니다.

분석 중 담당자가 수정한 최신 설명에 추가하고, 이미 한 번 공개한 사진 버전은 다시 덮어쓰지 않습니다. 사진/상태/출처가 변경된 오래된 결과는 공개하지 않습니다. 일반 큐 오류가 기존 수집·담당자 수정을 취소하지 않도록 분리했습니다.

**확인 SQL — 읽기 전용**

```sql
SELECT public.eeum_photo_ai_status();
SELECT item_id,state,attempts,last_error FROM eeum_photo_ai.jobs ORDER BY updated_at DESC LIMIT 20;
SELECT item_id,added_features,published_at FROM eeum_photo_ai.publications ORDER BY id DESC LIMIT 20;
SELECT count(*) FROM eeum_photo_ai.description_formats;
```

review는 분석 완료 상태입니다. 공개 저장 여부는 publications와 items.description으로 확인합니다. 전체 완료 건수라고 해석하지 않습니다.

**중지·복구**

90_pause.sql은 새 예약과 처리 모드만 중지합니다. 작업 완료/2분 lease 만료 후 93_restore_public_features.sql로 사진 특징 추가와 문장 정리 이력을 합쳐 최신 변경부터 복구합니다. 현재 설명이 당시 자동 저장한 값과 일치하는 행만 복구하며, 담당자가 이후 수정한 행은 건너뜁니다. 원본·비공개 결과·복구 이력은 삭제하지 않습니다. 91_rollback_keep_data.sql은 별도로 새 트리거 연결만 제거하며, 이미 공개된 설명을 복구하는 SQL은 아닙니다.

다시 자동 공개하려면 복구 결과/건너뛴 담당자 수정 내용을 검토한 후 07을 사용합니다. 복구한 동일 사진 버전을 다시 강제로 공개하는 상태 초기화는 하지 않습니다.

GitHub에는 feature/dugong의 새 SQL과 작업자 소스를 보관하면 됩니다. index.html 변경은 필요 없습니다. 패키지 생성은 node scripts/build-photo-ai.mjs /tmp/eeum-photo-ai-release이며 배포·push는 실행하지 않습니다.
