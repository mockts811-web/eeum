**최종 동작과 변경 근거**

사용자가 기존 물품과 새 물품 모두 AI 특징을 공개 특징에 자동 저장하도록 명시적으로 요청했습니다. 이에 따라 비공개 보관만 하던 결과를 필터링해 items.description에 추가합니다. 담당자의 보강/저장 클릭은 필요 없습니다. 정해진 습득/보관 상투 문구는 정리하고 물품명·색상·실질적인 설명은 유지합니다. 문장 정리와 사진 특징 추가의 변경 전/후 값은 비공개 description_formats/publications에 보관합니다.

기존 ai-parse v46, 수집기 v56, 작업자 v2, 프런트엔드는 유지했습니다. feature/dugong에서만 새 SQL·검증·문서를 작성하고, 앞서 만든 불필요한 화면 자동 채움 초안은 제거했습니다. main 기준 ce888cb1a7fc4bf8474157bd711601f638c7fbed는 수정하지 않았습니다.

**운영에서 확인한 근거**

PostgreSQL 17.11에서 스키마·RLS·ACL·Storage·실제 함수와 Cron을 확인했습니다. 현재 사진 후보는 8,000,000바이트 이하 등 실제 제한을 만족하는 278건입니다. 최초 첨부의 279건이나 현재 AI 성공 건수와 혼동하지 않습니다.

처음 우산 파일럿은 비공개 색상만 저장됐으며 완료 상태와 attempts=1을 그대로 유지했습니다. 첫 공개 파일럿 지갑 POL-F2026110700001532-1은 시간 초과로 retry에 들어갔고 원본 설명을 유지했습니다. 두 번째 지갑 POL-F2026110700001685-1은 실제 기존 AI 호출 후 접이식/가죽 재질을 공개 설명에 자동 저장했습니다. HTTP 200, committed=true, publications에 원래 설명과 새 설명/추가 특징이 보관된 것을 확인했습니다. 275건을 새 대기에 등록하고 all 모드로 신규·기존 처리를 활성화했습니다. 이는 전체 분석 완료를 뜻하지 않습니다.

**문장 정리 추가 검증**

사용자의 추가 요청에 따라 09_tidy_public_descriptions.sql을 적용했습니다. 습득/보관 문구 전체와 문장 끝/구분자를 확인해 제거하며, 이미 보강된 문장 사이에는 쉼표를 남깁니다. 중첩 괄호, A.P.C. 같은 이름, 갤럭시 S23 같은 모델명, 1,000원 같은 금액, 뒤에 이어지는 유의미한 별도 메모를 보존하고 두 번 정리해도 같은 값이 나오는지 검사했습니다. 사진 없는 신규 외부 물품의 자동 정리, 이미 보강된 문장의 AI 재호출 없는 정리, 두 종류 이력을 합친 원문 복구와 담당자 후속 수정 보존도 검사했습니다.

운영에서 기존 문장 958건을 정리했고, 해당 범위의 습득하여 보관하고 있습니다 잔여 문장은 0건입니다. 실제 카드지갑이 물품명/색상, 접이식, 가죽 재질 형태로 저장됐고 기존 분석 attempts=1을 유지했습니다. 새 이력 테이블은 RLS 및 역할별 접근 차단을 적용했습니다.

**중복 방지에서 보완한 실제 문제**

기존 수집기는 중복 items를 무시하기 전 사진을 upsert하므로, object.version/updated_at만 사용하면 같은 사진을 계속 재분석할 수 있었습니다. 유효한 Storage ETag가 있으면 내용 표식+경로+크기+MIME으로 식별하도록 수정했습니다. 없는 경우만 기존 객체 버전을 사용합니다. 현재 객체와 일치하는 기존 결과의 버전 표기만 변환했으며 완료 상태·시도 횟수를 초기화하지 않았습니다. 자체 SHA-256 계산이나 암호학적으로 동일 사진을 보장하는 기능으로 주장하지 않습니다.

**보안·엣지 케이스**

privacy=false와 내부 외형 어휘 검사를 모두 통과한 후보만 공개합니다. 이름/번호/영문 자유문/지시문/부정 표현과 지원하지 않는 문구를 거부하며 중복 문구는 추가하지 않습니다. 이 사전은 기관 공식 코드표 또는 사진 사실 검증이 아닙니다. 민감한 사진·추정 오류를 완전히 검출한다고 주장하지 않습니다.

공개 필드는 description만 변경합니다. 물품명·분류·기관·색상 코드·비공개 메모는 건드리지 않습니다. 분석 중 담당자의 최신 설명을 다시 잠가 읽고 추가합니다. 공개 완료 버전을 다시 덮어쓰지 않습니다. 출처·상태·사진 변경 결과는 무효화합니다. 트리거는 description 변경에 재귀하지 않습니다.

결과 저장과 공개 이력/설명 변경은 DB에서 처리합니다. 공개 저장 실패 시 해당 부분만 롤백하고 비공개 결과와 오류 표식을 보존합니다. 재대조에서 캐시로 저장만 재시도하며 AI를 다시 부르지 않습니다. 원자적 lease·전역 1작업·분당 1작업·하루 300작업·최대 3회 재시도는 유지합니다. 네트워크 응답 유실/기존 Gemini 내부 대체 호출까지 포함한 정확히 1회 과금은 보장하지 않습니다.

비공개 스키마/테이블/게시 보조 함수는 anon·authenticated·service_role에 직접 열지 않습니다. 작업 RPC만 service_role, 기관별 결과 조회만 소속 검사 후 authenticated에 허용합니다. 공개 설명 복구 RPC는 관리자만 실행합니다. SECURITY DEFINER는 빈 search_path와 명시적 EXECUTE 차단을 사용합니다.

**백업·복구**

publications에 변경 전 설명·자동 저장 후 설명·추가 특징·사진 버전·복구 시각을 보관합니다. 중지 후 최신 변경부터 역순으로 복구하며 문장 정리/사진 추가 이력을 함께 시간 역순으로 처리하고 현재 설명이 당시 저장값과 다르면 건너뜁니다. 이후 담당자 수정을 덮어쓰지 않습니다. 데이터·큐·결과·이력은 삭제하지 않습니다. 기존 담당자 삭제 기능은 FK cascade로 유지합니다. 적용 전 함수·ACL·상태·예약 해시 백업은 별도로 확보했으며 DB 전체 덤프/PITR 백업이라고 주장하지 않습니다.

**검증 범위**

로컬 40개 검사를 통과했습니다. PGlite PostgreSQL 18.6에서 실제 최초 설치/이전 업그레이드/공개 확장 DDL과 트리거/RPC/권한을 실행하고 기존 AI 핸들러의 HTTP만 격리했습니다. 공개 자동 저장·상투 문구 정리·원문/메모 보존·중복 완료·분석 중/후 담당자 수정·PII/이름/부정 표현 제외·공개 저장 실패 후 캐시 재시도·동일 ETag 재업로드·실제 내용 변경·완료 버전 전환·기관 권한·안전한 복구·기존 Cron 보존을 확인했습니다.

운영 PostgreSQL 17.11에서 실제 AI→공개 저장 파일럿을 확인했습니다. 실제 다중 세션 경합과 모든 278건의 결과 정확성 검증은 아직 완료되지 않았습니다. 전체 사진은 백그라운드에서 순차 처리되며, 실패/민감/새 특징 없음 항목은 원래 설명을 유지할 수 있습니다. 기존 ai-parse의 응답 제한은 25초이며 실제 시간 초과 1건이 재시도 대기에 들어갔습니다.

보안 Advisor의 [RLS 정책 없음 INFO](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)는 새 비공개 테이블의 의도한 직접 접근 차단입니다. 기존 기관별 조회의 [authenticated SECURITY DEFINER WARN](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)은 명시적인 기관 검사를 거칩니다. 기존 cancel_alert/rls_auto_enable 및 [유출 비밀번호 보호 설정](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)은 범위 밖으로 변경하지 않았습니다.
